# Prompt — 从论文集合生成系统发育树式的科学边界 B_t

## 目标
给定领域 F 的一批论文 { P₁, P₂, …, Pₙ }（及其 q.json、w.json 分析），把它们合并成一个**随 t 累积演化的**科学边界

    B_t = ( D_t, M_t, E_t, V_t )

并且 **D/M/E/V 每一维都以"系统发育树 (phylogenetic tree)"的层级结构**表示，而不是扁平列表。

## 四维定义（重述）
- **D_t 对象域** — 论文承认或引入的研究对象、任务、现象、数据对象；不是"领域名"。
- **M_t 方法域** — 论文认为有效、可用、合法的方法体系；不是简单列方法名，而是**方法的生态位**。
- **E_t 证据域** — 论文用来支撑主张的证据类型和证据标准；不是实验结果本身。
- **V_t 评价规则** — 论文用来判断成功、失败、价值和贡献的规则；不是结论。

## 树形结构准则（关键）
1. **正交轴优先**：每一维的根下第一层是 3–6 个**正交轴**（noun phrase 命名的"区分维度"，如"架构范式"、"同质性谱"、"数据完备性"）。每条轴之间**不可互相包含**。
2. **兄弟必须是生态位竞争者**：在同一父节点下的兄弟，应当是**同一生态位的可替代选项**，即
   "A 替代 B" / "A 扩展 B" / "A 是 B 的加强版" 三种关系之一。
   反例：把 `两阶段 MPNN 族` 与 `投影展开范式` 做同级兄弟 ✅（都是 backbone 选择）；
   把 `HGNN` 与 `简化 MLP 主干` 做同级兄弟 ✅（后者是替代前者）；
   把 `HGNN` 与 `Transformer 风格注意力` 做同级兄弟 ❌（不在同一生态位）。
3. **叶子才是具体条目**：类别名不是最终答案，类别下面才是可枚举的 item。
4. **深度合理**：每个叶子距根 2–4 层；避免过扁（<2 层）或过深（>5 层）。
5. **只有叶子带时间戳**：
   - `year = 此 item 首次被本批论文引入的年份`。
   - 内部类别节点的 year 由其后代最小 year 推导（用于时间过滤时该类别是否可见）。
6. **累积性**：一个 leaf 一旦被引入，在所有 t' ≥ year 都保留；**不删除、不改写**——演化只通过"新增枝桠"发生。
7. **保持可比性**：跨论文的同一 item 必须归并为一个叶子，不做重复，不写不同措辞。
8. **明确竞争**：如果新论文提出的方法**显式替代**了老方法，把两者放成同一父下的兄弟，并在父节点名里写出"替代 / 扩展 / 等价" 的语义。

## 命名规范
| 节点层级 | 命名形态 | 示例 |
|---|---|---|
| 维度根 | `D_t / M_t / E_t / V_t` + label | "方法域" |
| 第一层（正交轴） | **区分维度的名词短语** | "架构范式"、"结构学习策略" |
| 中间层（生态位家族） | 描述该生态位的名词短语 | "两阶段 MPNN"、"简化主干范式 (替代两阶段 MPNN)" |
| 叶子 | 具体 item（模型名 / 技术名 / 证据形态 / 评价规则条目） | "HGNN / HGNN+"、"Reparameterized 超边采样" |

**禁止**：用笼统词如 "其他方法 / 其他对象"、"更多数据"、"通用指标"；每个节点必须有清晰意义。

## 输出结构（JSON，每维一棵树）

```json
{
  "D": {
    "label": "对象域",
    "code": "D_t",
    "hint": "论文承认或引入的研究对象、任务、现象、数据",
    "children": [
      {
        "label": "<正交轴 1 名称>",
        "children": [
          {
            "label": "<生态位家族 / 或直接叶子>",
            "year": 2023,
            "children": [
              { "label": "<叶子 item>", "year": 2023 }
            ]
          },
          { "label": "<另一叶子>", "year": 2024 }
        ]
      }
      // ...
    ]
  },
  "M": { ... },
  "E": { ... },
  "V": { ... }
}
```

## 构造流程（建议步骤）

**Step 1 — 抽取候选 item**
对每篇论文的 q.json + w.json 逐字段抽取：
- D 候选 ← `w_object`, `q_background` 中被点名的对象/现象
- M 候选 ← `w_mechanism`, `w_type`, q 的 "现有方法"描述
- E 候选 ← `required_evidence`, `w_evidence`
- V 候选 ← `required_evaluation`, `w_evaluation`, `q_boundary_position_reason`

**Step 2 — 识别竞争对** (sibling pairs)
对方法域尤其要问：
- 这个 item **替代** 了哪个已有 item？
- 这个 item **扩展** 了哪个已有 item？
- 这个 item 与哪个已有 item **正交**？

同一生态位竞争者 → 同父兄弟；正交项 → 不同父。

**Step 3 — 归纳正交轴**
对同一维内的 item，问："要区分这些 item，我至少需要几个独立的轴？"
每条轴成为第一层分类。例：
- D 的常见轴：结构类型 / 同质性 / 完备性 / 下游任务 / 现象设定
- M 的常见轴：架构范式 / 结构学习策略 / 信号滤波 / 注意力 / 约束正则 / 联合优化
- E 的常见轴：实证 / 理论 / 鲁棒 / 可复现 / 基准与度量
- V 的常见轴：精度 / 结构 / 理论 / 范式 / 工程

**Step 4 — 归并同义项**
不同论文用不同措辞描述同一概念时，归并为一个叶子，选择最通用的表述。

**Step 5 — 打时间戳**
每个叶子 `year = min{ paper.year | paper introduces this leaf }`。

**Step 6 — 自检清单**
在输出前核对：
- [ ] 没有两个叶子语义相同
- [ ] 每条正交轴与兄弟轴互不包含
- [ ] 竞争者（A 替代 B）落在同父下
- [ ] 每个类别名是名词短语，描述区分维度
- [ ] 每个类别下 ≥ 1 个后代叶子
- [ ] 深度 2–4 层
- [ ] 叶子年份单调 ≤ 论文最新年份

## 演化视图 (可选，第二步产出)

除了一棵最终 B_{t_max} 树外，还应产出增量：

```json
{
  "delta": {
    "2023": [ { "dim": "M", "path": ["架构范式","两阶段 MPNN"], "item": "HGNN / HGNN+", "op": "add" } ],
    "2024": [ { "dim": "M", "path": ["架构范式","张量代数范式"], "item": "对称 CP 分解", "op": "add" } ],
    "2025": [ { "dim": "M", "path": ["信号与滤波设计"], "item": "低通+高通 Framelet", "op": "add" } ]
  }
}
```

`op` 可为 `add`（新叶子）、`split`（旧叶子细分出子类）、`sibling-of`（指明新叶子替代/扩展的老叶子）。

## 关于"未探索方向"

树的**空隙**不是 bug，是 feature。在可视化中，每条轴的"潜在分支但尚无叶子"的方位应显式渲染为灰色 `?` 节点，代表"B_t 尚未覆盖的方向"——例如"异质超图 × 动态结构"、"高阶超图 × 不完备视图"。这些提示可由 LLM 通过 D/M 轴的笛卡尔积自动枚举并剔除已覆盖项得到。
